# Business Logic & Feature Definitions

현재 코드 기준 핵심 로직.

## 1. 프로젝트 라이프사이클
```
[등록:관리자] → 진행중 → (완료 처리) → 완료 → "종료" 메뉴
                  ▲                          │(재개)
                  └──────────────────────────┘
```
- 상태는 `complete`/`reopen` 액션으로만 변경(일반 수정에서 제외).
- **완료 시 노출 자동 OFF**(show_in_dashboard/weekly=false), **재개 시 자동 ON**.
- "종료" 메뉴는 노출설정과 무관하게 완료 프로젝트를 항상 표시.

## 2. 프로젝트 노출 설정
- `show_in_dashboard` / `show_in_weekly` (프로젝트 등록/수정에서 체크).
- 대시보드 카드 = show_in_dashboard + 진행중. 주간보고 작성 드롭다운/취합 = show_in_weekly.

## 3. 프로젝트 수정 = 부분 업데이트 + 감사 로그
- `model_dump(exclude_unset=True)`로 **보낸 필드만** 반영(누락 필드 보존).
- 필드별 변경(name/code/full_name/유형/PM/기간/NAS/Git/노출)마다 `project_logs` 기록(actor·old→new). 마감일/상태/PM/팀원 변경 추적.
- 수정 UI(설정·상세)에서 저장 시 확인창(confirm) 필수.

## 4. 팀원 배정
- `PUT /projects/{id}/members`가 전체 교체(기존 삭제 후 재삽입), 추가/제외를 로그 기록.
- 프로젝트별 역할(pm/member). 설정·상세 양쪽에서 배정 가능.

## 5. 대시보드 표시/정렬
- 기본 정렬: **가나다(프로젝트명)**. 사용자가 드래그하면 **개인 순서**(user_project_order, `my-order`)로 저장 — 사람마다 다름.
- 유형 태그 클릭 시 해당 유형만 필터(재클릭/전체보기 해제). 필터 중 드래그 비활성.
- 카드/리스트 토글, 팀원은 **이름**으로 표시(직책순).

## 6. 이름 표시 정렬 (전역 규칙)
`app/ordering.py` — **(활성 우선) → 직책 순(센터장→팀장→차장→과장→대리) → 이름 가나다**, 직책 미지정은 뒤로.
적용: 인력관리 목록, 프로젝트/대시보드 팀원, 주간 멤버·전체취합, 선택 드롭다운. **비활성 사용자는 맨 아래**로 밀리고 이름 뒤 `(비활성)`.

## 7. 주차(Week)
- 생성/수정 시 **종료일 < 시작일이면 400(등록 불가)**.
- (year,month,week_num) 고유(**활성 주차 한정** 부분 유니크). 목록/생성/수정은 `is_deleted=false`만 대상.
- **삭제 = 소프트 삭제**(`is_deleted=true`, 관리자만): 화면에서만 사라지고 주차·주간보고 데이터는 **DB에 보존**. 하위 reports/entries도 그대로 남음.
- 목록에 참여 인원(활성+주간참여, admin 제외) 대비 완료 인원 표시.

## 8. 주간보고(Report)
- 저장 = 해당 (week,user) 보고의 엔트리 **전체 교체**. 상태 흐름 none→draft(저장)→done(작성완료)↔none.
- **작성/수정은 본인만**(관리자 포함 타인은 read-only, 403). **관리자는 작성 멤버 목록에서 제외**(작성 대상 아님).
- 멤버 목록 = 활성+주간참여 사용자 ∪ 해당 주차에 보고가 남아있는 사용자(비활성 포함, 과거 기록 열람용), admin 제외.
- 작성 드롭다운 프로젝트 = **진행중 + 주간보고 노출**만(완료 프로젝트 제외).
- **과거 보존**: 저장 시 `report_entries.project_name` 스냅샷 기록. 프로젝트가 삭제(`project_id`→NULL)돼도 과거 보고에 프로젝트명이 남아 그대로 표시(조회 시 현재명 우선, 없으면 스냅샷명).
- 프로젝트 상세의 "주간 진행"은 해당 프로젝트 참조 엔트리를 주차별로 취합(read-only).

## 9. 전체 취합(summary)
- 주간보고 노출 프로젝트만, "휴가 및 교육"은 항상 마지막 고정. 미리보기(복사용 팝업) 제공.

## 10. 감사 로그 / 관리이력
- `project_logs`에 마감일·상태·PM·팀원·필드 변경 이력 기록.
- 열람: **설정 > 관리이력** 탭(관리자 전용) — 좌측 프로젝트 목록 선택 → 우측 로그 테이블. (기존 프로젝트 상세의 "변경 이력" 탭은 이곳으로 이관.)

## 13. 데이터 보존 정책 (요약)
| 대상 | 삭제 동작 | 데이터 | 화면 |
|---|---|---|---|
| 프로젝트 | 삭제(하드) | 과거 보고 엔트리 보존(`project_id`→NULL, `project_name` 스냅샷) | 과거 보고에 프로젝트명 그대로 |
| 주차 | 소프트(`is_deleted`) | 주차·보고 전부 보존 | 목록에서만 숨김 |
| 사용자 | 소프트(`is_active=false`) | 과거 보고 보존 | `(비활성)` 접미어, 맨 아래, 활성화로 복구 |

## 11. 다크모드
- `ColorModeContext` + `theme.ts` 라이트/다크. 상단바 토글, `localStorage` 저장.

## 12. 초기화(seed)
- 앱 기동 시 admin 없으면 생성. 유형/상태 마스터는 마이그레이션 시드.
